## 4. 每日输出：必看摘要

### 4.1 收口逻辑：882 个标的 → 6 只

**问题**：两个定时任务各自输出全量池，日报要覆盖 **882 个标的/天**：

| 来源 | 数量 | 说明 |
|---|---|---|
| 趋势池 | 379 | 三周期共振 50 / 月周 2 / **月线多头 327** |
| 震荡池 | 25 | — |
| EMA 触发 | 162 | — |
| EMA 待回踩 | 288 | 存量，不是信号 |
| V2 常规 | 1 | — |
| V4 严格 + 补充 | 2 + 9 | — |
| 深回踩 | 16 | — |

**报出来等于没报。存量不是信号，变化才是信号。**

**核心诊断**：「月线多头 327 只」根本不是信号，它是**池的定义**——牛市里月线多头能占市场三成，零信息量。
「待回踩 288 只」同理，是每日固定的存量。这两项占了 615/882 = **70% 的噪音**。

**解决方案：统一收口成三档**

| 档位 | 上限 | 条件 | 用途 |
|---|---|---|---|
| **A 必看** | 6 只 | 过硬闸门 + 通道条件全部满足 | 今天真正值得看的 |
| **B 观察** | 15 只 | 只差一项，按「缺什么」分组列出 | 知道差在哪，但**不进买入池** |
| **C 存量** | — | 只报数量 | 看板里查，不进日报 |

**统一硬闸门（宁缺毋滥）**

| 门槛 | 值 | 为什么 |
|---|---|---|
| 非 ST / 非北交所 | — | 剔除不可交易与流动性陷阱 |
| 上市 ≥ 250 日 | — | 排除次新（无历史结构） |
| 股价 ≥ 3 元 | — | 排除仙股 |
| **20 日均额 ≥ 2 亿** | 原 5000 万 → **2 亿** | 实盘冲击成本；实测砍掉 121/253（48%） |
| ATR% ≥ 1.5% | — | 波动地板；低波动票走三角工作台的单独通道 |

**通道专属闸门（不同性质的信号不能共用阈值）**

- **trend 趋势**（三周期共振 / EMA / V4）：先验 `ADX ≥ 20`（否则用趋势逻辑判箱体票会判错），
  再要求「不追高」——距 20 日高 > −2% 时必须放量（量比 ≥1.2），且距 MA60 ≤ +30%。
- **revert 均值回归**（深回踩 / 震荡池）：必须贴支撑——箱位 ≤25%、当日收盘位置 ≥40%（不能一路砸到底）、距 MA60 ≥ −30%。
- **break 突破**（V2 三角）：必须放量（量比 ≥1.2）且确实创新高。

**两个防自欺设计**

1. **池内分位归一 + 池配额**：不同池的分数不可比（EMA 是 100−risk_pct、深回踩是质量分）。
   直接用原始分会造成「某个池分数天然更高」→ A 档被单一池占满。改为池内百分位，并限制 **单池最多 2 只**。
2. **市况行**：统计候选票中 ADX<20 的占比。实测 2026-11-03 为 **55%** → 震荡市，
   趋势信号天然打折。这解释了为什么当天 A 档以「深回踩 / 反弹」为主而不是趋势票。

**其他内建校验**

- **数据新鲜度**：stockdb 最新交易日 ≠ 今日 → 首行标「⚠ 数据滞后」，不假装是当日行情。
- **各池日期一致性**：任一池的 `tradeDate` 与基准日不符 → 告警，指出是哪个池没更新。
- **diff**：与上一交易日快照对比 → 🆕 新增 / 持续 N 日 / 掉出。同日重跑不累加天数。

**用法**

```bash
python common/daily_digest.py                 # 生成今日摘要（约 4 秒，40 行）
python common/daily_digest.py --verbose       # 附剔除原因审计
python common/daily_digest.py --top 5 --md x.md
```

**低波动通道（独立，不与 A 档混排）**

ATR% 0.8~1.5 的三角票（如长江电力、中国电建这类）会被常规池的 1.5% 波动地板挡住。
它们单列一段，标注 **平顶 / 抬高 / 收敛 达成进度（x/3）**，满 3/3 才叫「低波动三角」。
理由：波动小 → 绝对空间小，混进 A 档排序会占据要靠右尾的钱，只能当低仓底仓。

**观察名单联动**

`triangle-workbench/watchlist.json`（人工维护的关键位）现在会被摘要读取，按顺序判定：
`跌破 stop → ⚠失效` / `放量站上 breakout → 🔄换逻辑（箱体作废转趋势）` / `进入加仓区 → ➕` / `进入买点带 → 🎯` / 否则「无动作」。
若该票同时出现在 A/B 档，会标注「← 同时在 A/B 档」，避免两套系统各说各话。

**Jev 只评必看档**

原来 `jev_rank.py` 给 50 只「三周期共振」全跑 Jev。现在用 `--from-digest AB`：
读当日摘要快照，只对 A/B 档里的票做语义打分，**实测 379 → 10 只（2.6%）**。
所以趋势任务的执行顺序改为：扫描 → **摘要** → **Jev（收窄）** → gen_workbench_data。
摘要必须排在 Jev 之前，否则 Jev 不知道该评谁。

**已嵌入两个定时任务**（18:00 趋势 / 18:10 三角），作为报告的**主体**，池子只报数量不再逐条罗列。
18:00 用 `--only-fresh`（此时三角池还是昨天的，自动跳过，不混入昨日数据）；
18:10 用默认（两边都是当日数据）。

**★ 顺带修掉的一个数据 bug（影响面大，值得记）**

`qfq.adjust_recs()` 内部假定输入按日期**升序**（`adjust()` 从最后一行往前滚动累积因子）。
但 stockdb 的 `cmd=vals` 默认返回**降序**。降序输入会让因子作用到错误的一端——
最新价被放大成「整段区间的分红因子之积」。

实测 601669 中国电建：错误调整后 4.54 → **5.045（虚高 11.1%）**，于是 ATR%、箱位、距均线全被污染，
它差点被误判进 A 档。

修法：在 `adjust_recs()` 内部强制按日期升序计算，再把结果映射回调用方传入的原始顺序。
这样 15 个调用点都不用改，也不会再算错。


## 6. 输出模板

```
【一句话】
【P0 数据说明】dataAsOf / 复权方式 / 数据源 / 巡检结果 / **是否 ST（必须写"非 ST"）**
           ★ **分红方案逐条对账结果**（条数 / 金额 / 累计复权因子）；不得只写 needs_div=False
【P1 池子 + 行业】命中哪些 / 不中原因 / 所属行业 + 同业对比
【P2 技术】日线缠论 → 周线缠论 →（跌幅>30% 加月线）→ 指标 → 关键价位表
【P3 基本面】成长/盈利/含量/杠杆/隐患
           ★ 归母 与 扣非 必须并列
           ★ OCF/净利 必须双口径（累计 / TTM）取更差
           ★ **分母污染闸门**：非经常性 X 亿 / 归母 Y%（>30% → PE 与分位全体作废）
           ★ PE 分位失效时改用 PB + 一致预期 PE（扣非口径）
           ★ **PE 与 PB 分位背离时**：写出形态（高 ROE 成长 / 盈利低谷 / 真便宜 / 双贵），
             PE 低分位不得单独当买入理由
           ★ 报 PEG 时**必须附增速回落敏感度表**（增速降到 X% / Y% 时 PEG 各为多少）
【P3.5 事件面】业绩异动的真实原因属于：政策型 / 一次性损益型 / 报表结构型
             ★ 逐个回答"这笔钱明年还会不会有"
【P4 主力行为】八问 + 资金流四层 + 5日与20日对照 + 融资拥挤度 + 北向
【P5 赔率与仓位】rr 四口径（2 止损 × 2 目标）+ 仓位上限 + 多级别共振三票
           ★ 股息率>2% 或 >ATR% → **补含息 rr + 股债利差反向定价表**
【P5.5 进场方案】交易类型 → 触发条件 → 分批/止损/目标 → 有效期
           ★ 非趋势型资产 / 两组 rr 结论相反 → **分「交易口径」「配置口径」两套写**
【P6 Jev】信号可信度 + 进场时机 + 置信 → 落在哪个象限
           ★ 非趋势型资产先过「适用性闸门」：可信度降级解读、时机不降级、矛盾逐条列出
【P7 横向对比】（≥2 只时）逐层筛选：否决 → 分层 → 排序 → 择时
【免责】研究口径，不构成投资建议
```
