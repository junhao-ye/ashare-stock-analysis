# ashare-stock-analysis

A 股个股深度分析标准流程 **v4.6**，做成可复用的 Agent Skill。

不是「给个目标价」，而是给**结构位置 + 多口径赔率 + 失效条件**，并把「哪些数字不可信、为什么」写死在闸门里。

> ⚠️ 研究口径，**不构成投资建议**。本仓库输出的是分析过程与失效条件，不是买卖指令。

---

## 它解决什么问题

个股分析最常见的错误不是「算错了」，而是**「数字是真的，但读法是错的」**。这份流程的价值全部来自踩过的坑：

| 表面上看到的 | 实际是什么 | 差多少 |
|---|---|---|
| 净现金 1269 亿，EV/EBIT **6.80**，极度低估 | 货币资金 1489 亿 < **合同负债 1613 亿**（客户节点款）→ 实为净负债 344 亿 | EV/EBIT 实为 **15.2**，差 **2.24 倍** |
| PE_TTM 47.19，落 **2.3% 分位**，六年最便宜 | 25.11 亿一次性收益把分母撑大，占归母 **60.7%** | 扣非 PE 实为 **103.9×** |
| 归母 **+129.67%**，高增长 | 去年起吸收合并并表，Q1 +251% 是纯并表台阶 | 唯一可比是 Q3 单季 +68% |
| 毛利率「环比持平」 | 季节性行业只能用同比 | 同比是 **−0.44 / −3.87 / −6.20pt** 加速恶化 |
| 应收 **+154%**，放宽信用 | 比期末余额是错的，要看周转天数 | 118 → 115 天，反而略改善 |

**结论：凡是比值类指标，必须两个口径互校，取更差的那个。只用一个口径就下结论的，先假定自己错了。**

## 七道硬闸门

流程有十一个阶段，但真正决定成败的是「哪一步不过就该停」。

| # | 闸门 | 判据 | 不过怎么办 |
|---|---|---|---|
| 1 | ST 预筛 | 名称含 ST/\*ST，或涨跌幅 ±5% | 终止，说明不适用 |
| 2 | 分红逐条对账 | `needs_div()` 返回 False **不能**证明不需要复权 | 补 `div_cache` 重算前复权 |
| 3 | 分母污染 | `abs(归母−扣非)/abs(归母) > 30%` → PE 与 PE 分位**全体作废** | 改扣非 PE + PB 分位 + EV/扣非 |
| 4 | EV 必扣合同负债 | `合同负债/货币资金 > 50%` 强制扣，`>100%` 禁止把净现金当安全垫 | 重算 EV/EBIT，写明原值高估几倍 |
| 5 | ADX 方向闸门 | ADX < 20 → 无趋势 | 方向性结论作废，只留区间与失效位 |
| 6 | Jev 置信闸门 | 置信 < 0.3 → 该格作废；分数与结论同向但置信低 = **伪一致**，同样不得引用 | 写「本格不可用」，结论不得依赖它 |
| 7 | 目标必须写明 | 每个 rr 都要有目标价 + 持有期 | 只给「上涨空间」的 rr 一律剔除 |

## 安装

```bash
git clone https://github.com/junhao-ye/ashare-stock-analysis.git \
  ~/.workbuddy/skills/ashare-stock-analysis
```

依赖（本机已具备则跳过）：

- Python 3.12+，`numpy` / `pandas` / `TA-Lib` / `czsc` / `pyyaml`
- 本地行情库 stockdb（`http://127.0.0.1:7899`）
- 可选：easy-tdx（行业 / 估值分位 / 快照）、westock MCP（财报 / 筹码 / 资金 / 研报）、Jev（语义自洽）

任一环节缺失时流程要求**显式标注缺口**，而不是用旧缓存或占位值硬跑。

## 使用

装好后直接说人话即可触发：

```
分析中国船舶
600150 这只票能进吗
帮我做一份宁德时代的深度报告
这票赔率怎么样、止损放哪里
它的扣非和归母差这么多，是什么原因
这几只票横向对比一下谁更强
```

**不会触发**的场景（它们各自有更合适的工具）：全市场选股筛选、裸取数/写接口、缠论理论讲解、指数与宏观、组合层回测。

### 开工前自检

```bash
python scripts/preflight.py --code 600150 --root /path/to/workspace
```

四探：stockdb 连通性 + 最新交易日、easy-tdx（顺带验行业）、Jev 凭据、环境版本。自动剥 `sz/sh` 前缀（stockdb 的 `t=` 只认纯数字，带前缀会**静默返回空表**，不报错，最容易漏），并判定 `dataAsOf`。

实测一次输出：

```
  stockdb      ✅  6290 根 | 最新 20261109 | 收 35.01 | 0.13s
  easy-tdx     ✅  最新 20261110 | 收 34.16 | 行业 ['航海装备']
  Jev          ✅  凭据已配置
  环境              numpy 2.5.3 | pandas 3.0.6 | talib 0.8.1 / 201 函数 | czsc 1.0.2
  dataAsOf     ✅  20261110
  两源一致         ❌  否（stockdb 20261109 / tdx 20261110）
```

最后一行就是它存在的理由：**「两个源默认同一天」是错误假设**，所有报告必须标注 `dataAsOf`。

### 报告自检

```bash
python scripts/check_tables.py 报告.md
```

表格里多写一个 `|` 就会整表错位，肉眼扫几百行看不出来。这个脚本在构建本仓库时抓出过源文档一处真实断表。

## 两个设计取舍

**1. references 逐字迁移，不重写。**
方法论的核心资产是那些具体数字——「差 2.24 倍」「−0.44/−3.87/−6.20pt」「118→115 天」。概括会丢掉唯一能让人记住「为什么必须扣合同负债」的细节。所以正文机械切分、数值零改写，只新增标题层级和一行导读。

**2. 切分用脚本，不手工复制。**
2,100 行手工搬必然漏段，且数值容易被顺手改错。`scripts/rebuild_references.py` 按「行号 + 锚点文本」双重定位，锚点不符直接失败，不会静默错位；输出幂等（两次运行 md5 一致）。方法论升版后改 `SPEC` 里的边界重跑即可。

## 已知限制

- **不可移植**：依赖本地 stockdb、本地脚本与特定目录结构，`data-interfaces.md` 与 `preflight.py` 含本机绝对路径。换机需改路径。
- **只做单票**：P7 横向对比仅支持手工给定的 2–10 只，不做全市场排序。
- **缺口已显式化但未消除**：并表年份的 PE/PB 时间序列分位不可构造、上市不足 3 年只能做截面分位等，见 `references/known-gaps.md`。
- **不适用**：ST / \*ST、指数、板块、宏观、组合层。
